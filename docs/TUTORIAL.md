## 0. 先说清楚：我们到底做了什么

**Logseq 是什么**：一个"大纲笔记"软件。你写的每一行是一个**块（block）**，
块可以缩进成子块；块里可以写 `[[另一个页面]]`，软件就自动帮你把两个页面连起来，
还能反过来告诉你"谁引用了我"。文件其实是**普通的 Markdown**，存在你自己电脑的文件夹里。

**我们做了什么**：Logseq 本体是 ClojureScript + Electron 写的（2.5 万次提交，很庞大）。
我们用**另一套技术栈**把它最核心的那部分重写了一遍——就是
"读 Markdown 文件 → 变成大纲给你编辑 → 存回 Markdown → 顺便算好链接和搜索"。

**没做什么**：插件系统、白板、卡片复习、云同步、手机 App。这些**不在**本次范围内，
不要对外说"我复刻了 Logseq"，要说"我重写了它的核心"。

## 1. 三个技术栈，各干各的活

用**餐厅**打比方最准：

| 角色 | 技术 | 干什么 |
| --- | --- | --- |
| 🏠 店面 | **Tauri** | 把网页装进一个桌面窗口里。它不写业务逻辑，只负责"开窗、打包成 .exe" |
| 🧑‍🍳 服务员 | **TypeScript + React** | 看得见的那层：按钮、文本框、点一下有反应 |
| 👨‍🍳 后厨 | **Rust** | 真正干活：读文件、解析、算链接、搜索、写盘 |

**为什么不全用 JavaScript 写完算了？**
因为任务要求用这套栈——而且它确实有道理：**后厨（Rust）不依赖店面（Tauri）**，
所以后厨可以**单独测试**，不需要开窗口。这一点后面第 5 节还会说，它是这个项目最重要的设计决定。

> Tauri 和 Electron 的区别：Electron 在每个 App 里塞一整个 Chrome（几百 MB）；
> Tauri 用**系统自带的网页内核**（Windows 上是 WebView2），所以体积小得多。

## 2. 整个项目的心脏：**块树（block tree）**

这是你**必须**先搞懂的一个概念。搞懂它，这个项目就懂一半了。

### 同一个东西的两种长相

**在文件里**，它长这样（就是一坨文本，靠**缩进**表达层级）：

```markdown
- 今天学了块树
  - 缩进表示子块
  - TODO 还要写个练习
- 另一件事
```

**在内存里**，它变成一棵**树**：

```
"今天学了块树"
├── "缩进表示子块"
└── "TODO 还要写个练习"
"另一件事"
```

- `今天学了块树` 有 **2 个子块**；`另一件事` 是它的**兄弟**（同级）。
- 在文件里，"谁是谁的孩子"是靠**前面有几个空格**（缩进）看出来的；
  在内存里，是靠 `children` 这个数组。

### 所以整个软件的核心工作，就是这两个方向的翻译：

```
   Markdown 文本  ──解析(parser)──▶  块树
        ▲                              │
        └──────序列化(serializer)───────┘
```

- **解析** = 把"带缩进的文本"读成"树"（`crates/core/src/parser.rs`）
- **序列化** = 把"树"写回"带缩进的文本"（`crates/core/src/serializer.rs`）

这两个函数**必须互为逆运算**：树 → 文本 → 树，应该和原来一模一样。
这个词叫**幂等**，我用测试专门盯着它（见第 6 节）。

> 💡 **为什么非要转来转去？** 因为"文本"适合存在硬盘上、适合用别的软件打开；
> 但"文本"很难做逻辑——你没法方便地问一坨字符串"你下面有几个孩子"。
> 树适合做逻辑，但不适合存盘。所以两边都要，中间翻译。

## 3. 你敲一个键，发生了什么

这是**数据流**，面试常问。用"你在块里敲了个字"举例：

```
① 你打字
   BlockRow.tsx 里的 <textarea> 触发 onChange
        │
        ▼
② 改内存里的树
   store.ts 调 mutateBlocks()，内部用 lib/outline.ts 的纯函数
   把"旧树"变成"新树"（不是就地修改，是造一棵新的）
        │
        ▼
③ 等 400 毫秒（防抖）
   如果你还在连续打字，就取消上一次的定时器，重新计时
        │   ← 这一步是为了不要每敲一个键就写一次硬盘
        ▼
④ 把【整页】的树发给 Rust
   api.ts 的 savePage() → Tauri 的 invoke("save_page", { page })
        │
        ▼
⑤ Rust 序列化 + 原子写盘
   serializer 把树变回 Markdown 文本
   先写到临时文件，再 rename 覆盖原文件  ← 断电也不会写坏
        │
        ▼
⑥ Rust 重建索引
   重新扫描所有块 → 更新搜索索引、反向引用数据
```

**注意 ④ 的"整页"**：不是一个块一个块地同步，而是**每次把整页的树整个发过去**。
看着"笨"，但换来一个巨大的好处：**永远不会出现"一半改了、一半没改"的中间状态**。
这是工程上的取舍——用一点带宽，换掉一整类很难查的 bug。

## 4. 三个文件，看懂 80%

别一上来就看几十个文件。按这个顺序读，性价比最高：

| 顺序 | 文件 | 看什么 |
| --- | --- | --- |
| 1️⃣ | `crates/core/src/model.rs` | `Block` 结构体：一个块有哪些字段（id、内容、标记、子块…）。**这是全项目的词典** |
| 2️⃣ | `crates/core/src/parser.rs` | `parse_page()`：怎么把 Markdown 读成树。先看开头的注释块，那里画了格式说明 |
| 3️⃣ | `crates/core/src/serializer.rs` | `serialize_page()`：怎么把树写回 Markdown。很短，和 parser 对着看 |
| 4️⃣ | `src/lib/outline.ts` | 前端怎么改树：缩进、合并、移动。全是"进旧树 → 出新树"的纯函数 |
| 5️⃣ | `src/store.ts` | 状态存哪、什么时候保存 |
| 6️⃣ | `src-tauri/src/commands.rs` | Rust 对外开放的"服务窗口"：所有 `#[tauri::command]` |

**先别碰**：`src/components/GraphView.tsx`（力导向那套数学）、`src/mock.ts`（只是浏览器演示用的假后端）。

## 5. 四个工程判断（这些才是能拿出去讲的东西）

写代码谁都会，**说清楚"为什么这么写"**才是加分的。这四个判断你可以直接背：

**① Rust 核心不依赖 Tauri**
`crates/core/` 里的代码**完全不 import Tauri**。好处：
后端逻辑可以脱离桌面环境单独跑测试，编译也快得多。
这叫**分层**——外壳（易变、依赖多）和领域逻辑（稳定、纯净）分开。

> **这条不是理论，它救过我们。** 这台机器上空手起步：没有 MSVC、没有 MinGW、
> 没有 Rust，连 rustup 的 shim 都是坏的。在**外壳一行都没编译成功**的那些小时里，
> 我们**照样拿到了全部测试全绿的结果** —— 因为核心不依赖 Tauri。
> 如果当初把解析逻辑写在外壳里，那段时间能说的就只剩"它应该能跑"。
> （后来外壳也修好了：一共 8 个问题，每个都写清楚了根因，见 `docs/DELIVERY.md` 第二节。）

**② 解析只写一份，写在哪边？写在 Rust。**
如果前端也用 JS 写一份解析，就有了**两套实现**。哪天改了格式，两边不一致，
就会出"界面看着对、存到文件里不对"这种**最难查的 bug**。
所以：**前端只管"改树"，Rust 独占"树 ↔ 文本"的翻译权**。

**③ 搜索索引每次重建，而不是增量补丁**
每次保存后，把所有块重新扫一遍建索引。听着很笨（O(n)），
但换来一个保证：**索引永远不会和数据不一致**。个人笔记几千个块，重建毫秒级。
"宁慢勿错"——尤其在这种"错了也不报错"的地方。

**④ Markdown 文件是唯一事实来源**
内存里的一切（块树、索引、反向引用）都只是**缓存**，随时可以丢掉重建。
所以：没有数据库、没有迁移、没有隐藏状态。**你把 App 删了，笔记还是那堆 .md 文件**。

> 这四条其实是一件事：**把"可能出错的地方"要么消灭，要么让错误立刻暴露**。
> 你之前做 Lux 时担心的"静默失效比功能缺失更危险"，在这是同一套思路。

## 6. 验证：怎么证明"它是对的"

**别信"我觉得没问题"，要跑给人看。** 这个项目里有三种证据，而且都真跑过：

### 证据一：往返幂等测试（Rust）

`crates/core/tests/roundtrip.rs` 里最关键的一条：

```rust
// 树 → 文本 → 再解析 → 再序列化，两次文本必须一模一样
assert_eq!(once, twice, "serialisation is not idempotent");
```

为什么这条最重要？因为只要它成立，"你的笔记不会因为打开一次就被改乱"。

跑法（一步到位）：

```bash
cd E:/git/logseq-tauri
source scripts/rust-env.sh      # 把本仓库内的 Rust 工具链加进 PATH
cd crates/core && cargo test
```

**实际结果**：`26 passed; 0 failed`（16 个单元测试 + 10 个集成测试）。
另外 `cargo clippy --all-targets -- -D warnings` 也是**零告警**。

### 证据二：界面真的能跑（截图）

**桌面程序本体的截图**：`docs/screenshot-desktop.png` —— 这是 `target/release/openseq.exe`
**真的以原生窗口跑起来**时截的，不是浏览器、不是示意图。有原生标题栏、
左侧页面树、右侧图谱、底部状态栏，全是真的。

> 这张图是我**能拿出的最强证据**：它一次性证明了「Tauri 外壳编译成功 → WebView2 初始化
> → 内嵌前端被加载 → UI 渲染正确 → Rust 命令返回的数据正确（左侧页面的块数、
> 图谱的节点和连线都来自真实解析）」这一整条链路。

**浏览器截图**：`docs/screenshot-app.png` 和 `docs/screenshot-graph.png`，方法是用静态服务
把前端构建产物起来，让 Edge 无头模式打开并截图 —— 适合快速调 UI，不用重编 Rust。

> ⚠️ 这两张**浏览器**截图跑的是**浏览器演示后端**（`src/mock.ts` 里的假数据），
> 所以它证明的是"**前端**能跑"，**不能**证明 Rust 后端对。Rust 后端由证据一和证据三负责。
> 而上面的**桌面截图**才连 Rust 后端一起证明了。

### 证据三：测试抓到过一个真 bug —— 这个例子值得你记住

第一次跑 `cargo test`，16 个测试里有 1 个**失败**了：

```
assertion `left == right` failed
  left: ""
 right: "ship it"
```

也就是说，`- TODO [#A] ship it` 这一行，解析出来的块正文是**空的**。

**为什么？** 优先级用的是正则 `^\[#([A-Za-z0-9]+)\][ \t]*(.*)$`。
这里面 `(.*)$` 表示"剩下的所有内容"——它是**贪婪**的，已经吞到了行尾。
而我当时写的是"取整个匹配结束之后的部分"，等于把正文也切掉了，剩下空字符串。

**为什么值得记住？** 因为这个 bug **`cargo check` 完全发现不了**：
代码没有类型错误、没有借用错误，编译全绿，功能却是错的。
只有真的跑起来、真的断言结果，才能抓到它。

这类"**不报错、只安静地给出错误答案**"的问题，是你在 Lux 里最担心的一类问题
（"静默失效比功能缺失更危险"）。它的通用解法就三条：

1. 把逻辑放在**能被单独测试**的地方（这就是 Rust core 不依赖 Tauri 的真正原因）；
2. 断言**具体的值**，不要只断言"没崩"；
3. 找一个**能区分对错**的输入（`TODO [#A] ship it` 比 `TODO ship it` 更有鉴别力，
   因为只有带优先级的才走那条有 bug 的分支）。

## 8. 三个练习（做完你就真的会了）

**练习 1（读代码）**：打开 `examples/demo-graph/journals/2026_10_11.md`，
手工在纸上画出它对应的**块树**（哪个是哪个的孩子）。然后去

**练习 2（改代码·小）**：`crates/core/src/model.rs` 里有个 `TODO_MARKERS` 常量。
现在有 7 个标记（TODO/DOING/NOW/LATER/WAITING/DONE/CANCELED）。
试着加一个你自己的（比如 `BLOCKED`），然后想：**还有哪里需要跟着改？**
（提示：搜索框、UI 上的颜色、解析逻辑）
——这个练习的目的是让你体会"改一个常量会牵动多少地方"。

**练习 3（改代码·中）**：图谱视图目前**不能缩放**。

给它加一个"滚轮缩放"：监听 `wheel` 事件，改一个 `scale` 变量，
在 `paint()` 里用 `ctx.scale()` 或手动乘坐标。
（这是我在示例日记里留的 `TODO` 之一，做完可以把它改成 `DONE`。）

## 附：还需要背的几个词

| 词 | 一句话解释 |
| --- | --- |
| **块（block）** | 大纲里的一个节点，可以嵌套 |
| **图谱（graph）** | 就是一个文件夹，里面全是 `.md` |
| **反向引用（backlink）** | "谁引用了我"，由全图扫描算出 |
| **序列化 / 反序列化** | 内存对象 ↔ 文本 的互相转换 |
| **幂等（idempotent）** | 做一次和做多次结果一样（这里的指"存盘不会越存越乱"） |
| **防抖（debounce）** | 连续触发时只在停下来之后执行一次 |
| **原子写盘** | 要么完整写成功，要么完全没动，不存在"写了一半" |
| **分层（layering）** | 上层依赖下层，下层不知道上层的存在 |
